# Requirements review

The implemented core covers class creation and summaries, student identification and saved-browser continuity, seat allocation, countdown and expiry, confirmation, cancellation, and application history. Database tests cover capacity, duplicates, ownership, idempotency, lock-time expiry and persistence. Earlier clean-source Compose recreation evidence is in `CONTAINERS.md`.

The revised administrator requirement supersedes the original demo assumption. Class creation now requires a private `Admin__AccessKey`; the backend rejects missing or incorrect credentials. The public portal has an Admin button and code prompt before showing class creation and the paginated application register. Public classes support name/shift and availability filters; the administrator register supports class and status filters. This is a shared key for the local demo, not an individual account/role system. Student identity still uses the assignment's header model.

Periodic catalog refreshes no longer toggle loading controls. Detail refreshes keep the existing panel and payment buttons steady, while expiry, mutations and actual errors still disable unsafe actions. A mutation aborts its pending detail read; late results are ignored. Regression tests cover these behaviors.

Outstanding verification: mobile viewport, a complete browser-process restart, hosted CI for the latest changes, and final public-repository/submission checks. Existing tab-reopen and two in-process-host checks do not establish those results. The historical Compose persistence run preceded the administrator change; its runner now supplies a synthetic administrator key for future runs.
